# A03：原子授权、累计预算与Redis准入

2026-11-08。按已确认的OpenSpec与单代理计划实施。当前完成的是授权/计账基础设施和Session仓储接缝；完整Run/Job及应用装配继续由A04以后承担。

## 实现与边界

- control白名单函数以真实`session_user`确定platform/travel/maintenance身份；owner为NOLOGIN，固定`search_path=pg_catalog`，限定表名。运行账号不直接读写control表或跨服务业务表。显式撤销PUBLIC函数执行权，私有helper不向运行账号开放。
- 提交按Session→Run→context→scope持SHARE锁直到本地事务结束；撤回按同序列取排他锁。真实Travel业务行验证了“提交先取得锁可完成、撤回先提交则拒绝”。授权还核验主体、目标、能力、上下文代次和有效期限。
- `platformpg`沿用现有`auth.Store`接口；SQL包装在一次事务内创建/撤回Session及guard。运行账号无Session直接写权限；失败不会遗留孤立guard。AuthService接口与行为不变。
- 准入从开始就取得Run预算UPDATE锁，随后按排序资源锁登记原`outbound_calls`。父子scope按原Run汇总；后台operation独立。四维预占为模型次数、工具次数、token上界和费用微单位，拒绝缺项、负数、小数、溢出和伪造免费模型尝试。
- 已知usage只结算一次；次数不因零token使用量退款；未知usage保留原预占及保守占用，授权关闭后仍可结算原事实。只有确认未发送才释放相应预算。
- control_rpc也进入同一调用/资源账，四维供应方预占为0；仍受资源硬并发和scope期限约束。后续A09/A11承担独立轮询频率及传输重试限制。
- Redis Lua按原attempt ID获取/续持/释放；最多等待2秒且服从调用者剩余期限，SDK命令重试关闭。每次许可操作使用短PG资源锁核对generation，丢键后从原调用账重建；未知调用不能提前释放。PG硬上限覆盖Redis丢写，Redis不可用拒绝新准入但不影响原调用结算。代价为每个许可操作增加一次短PG事务。
- Run固定deadline与Session绝对到期独立保存；Session剩余时间较短不会改写Run期限，每次授权及等待资源锁后仍检查Session是否到期。

`control.Client`只处理授权/调用账。实际Job/Task/operation的当前worker、epoch、租约及提交时刻期限由所属仓储在同一事务内核验，后续A04/A05/A10/A12实现；不能把本阶段scope检查当成完整执行围栏。
