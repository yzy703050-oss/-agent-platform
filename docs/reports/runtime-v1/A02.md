# A02：新库初始化与账号隔离

2026-11-07。用户明确旧数据库数据均可舍弃；正式规格、proposal、design、数据库说明及A02/A16计划已同步为全新部署。旧数据导入、历史读取账号、兼容字段和旧断点收尾不属于本次交付。

## 实现

- `migration.Provision`是管理员显式入口，创建三个NOLOGIN owner、三个组件迁移登录和平台/Travel/Maintenance运行登录；标记绑定数据库OID，拒绝接管无关角色或schema。
- `migration.Apply`只允许对应组件迁移登录，按control→platform→travel顺序串行提交；各自记录SQL摘要和版本，重放验证摘要，不在API启动时运行。
- 三个schema具有本服务的表、唯一键、复合归属FK、状态/租约/次数CHECK和到期扫描索引。跨schema业务FK为零，control私有表不向运行角色开放。
- 新部署不执行旧001～005。原文件仅作为尚未替换旧代码的回归材料；新库不创建旧public业务表，不导入旧账号、消息、计划、记忆或checkpoint。
- SQL文件固定LF，确保Windows与Linux嵌入及摘要一致。CI提供显式隔离PG管理配置；运行测试缺PG时失败，不SKIP。
