# A01：领域DTO、严格协议与JCS

- 已手写原Schema的63个同名领域/运行DTO，内部租约与LimitSnapshot独立；不依赖Eino、不替换legacy model。
- DecodeStrict按正式Schema验证未知字段/必填/状态分支，并在数值规范化前检查整数和常量精度；拒绝重复键、非法Unicode、非有限数、不安全整数、数值下溢、多JSON值与超限。日期/时间/URI显式校验；成功后才替换目标，省略/null不混同。
- InputHash实现原协议对象schema_version+args+scope的JCS/SHA256；固定夹具hash一致，UTF-16排序/浮点/转义向量通过。ValidateResult区分受理/终态，核对原Task/key/hash，最终failed可以带真实partial。
- RED证据：首次缺runtimev1/DecodeStrict；整数指数记法、接近整数的小数、非法+24:00时区和验证入口A01未登记均先复现失败，再修正转绿。测试工厂漏PlanPatch/TravelTaskLookup已补，未改正式夹具。
- GREEN：runtimeprotocol共63项测试/子测试（含43份原夹具）通过；全后端442通过、100跳过、0失败；跳过依赖与A00一致，见[A00明细](A00.md)。脚本5项通过；go vet两新包、go mod verify退出0；验证脚本A01实际运行测试并构建。
