# A05：共享查询、模型计量与证据传输

2026-11-08。依据原OpenSpec与单代理计划实施。本阶段交付可复用服务和仓储边界；API/Worker/Travel进程装配、正式计划接受结果和真实模型验收仍在后续任务。

## 实现与证据

- `toolquery.Service`提供不依赖计划的hotel/train/weather/web/policy查询。两个服务使用各自连接和事实表，固定schema的runtimepg不接受任意schema名。每次发送、结果保存和缓存读取核验scope、所属Job/Task、worker/epoch及固定期限。实际工具成功、空成功和证据同事务提交；故障提交窗口区分未保存可重算与已保存必须复用。
- 逻辑输入以JCS摘要固定。四次物理尝试与next_retry_at保存在原control调用账，服务重建不重置次数；采用1/2/4秒全抖动与Retry-After，不叠加旧HTTP重试。网络完成不明保留unknown、预算及许可，不透明重发。网页零自动重试，运行时保留官方解析器但抑制翻页，成功结果可复用。
- 原供应方响应、实际查询、来源、demo标记与候选均保留。酒店地点能力不生成价格、库存或订单。已知车票价格保留整数分与person计价单位；未知计价基础保持unknown。拒绝工具域冲突及live/demo候选混合。提供web与HTTP policy适配，保留执行追踪、版本和降级原文。
- `llm.NewRuntime`隔离旧NewTravel重试；`NewMetered`覆盖Generate、Stream和WithTools，包括后台operation。预留依据运维确认的供应方输入硬上限、实际输出max_tokens及显式微额单价；上下文估算不能充当费用硬上限。完整模型消息、工具调用及响应元数据先保存再返回；流式完整消息先保存再EOF，半流不保存为完整答案。缺失wire用量不采纳SDK补零，保留原预留。绑定工具冻结；相同键按原输入、实际通用选项、工具、模型与执行配置指纹复用。
- 前台接纳即保存原限额投影；后台限额随scope签发内容一起计算摘要，消息用operation_id归属，不伪造前台Run。已保存模型输出仍受当前授权约束；原尝试结算允许完成此前已发出的会计事实。
- MCP使用官方Go SDK v1.8.0，显式固定2025-11-25，按配置服务身份复用会话与HTTP池。Bearer只在认证头，可信_meta不进入模型参数；禁独立GET SSE、SDK重连、重定向及body重放。完整响应上限1,000,000字节，包括被忽略的RPC外壳。
- 内部证据GET以Bearer确定peer，再核验scope内精确的来源服务/ID/版本/hash清单。响应为原不可变记录的JCS内容；接收方核验身份、hash、用户、会话、来源和有效期，网络前后核验自己的执行权。imports保留原payload与授权来源，候选ID不改，不生成假的本地查询。每次复用导入证据重新向源端核验，撤回源消息后缓存也拒绝。remote引用为注册slug加原ID的UTF-8 SHA-256；slug最多32字符，引用不超过160字符。
