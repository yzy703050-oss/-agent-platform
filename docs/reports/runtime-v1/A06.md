# A06：正式计划、原子Patch与任务版本

2026-11-08。依照原OpenSpec和单代理实施计划完成本阶段服务/仓储边界；专业MCP受理、Plan-Execute循环和应用装配仍在A07/A10/A13。

## 实现

- `travelplan.Service`提供Create、ApplyPatch、View和AcceptQueryResult。首次提交完整定义，之后按稳定Stop/Leg/Task/Requirement/Selection ID提交Patch。私有副本按顺序应用操作后统一校验结构、参数表示、最终引用图和查询依赖无环；拒绝受保护路径、任意JSON Pointer、数组下标、重叠set/unset及旧版本覆盖。校验后的序列化值是执行依据，隐藏的Go Field.Value不能绕过字段存在性和请求摘要。
- 有效Task定义比较包括Task本身、适用要求、关联Stop/Leg和时区。改变Task后增加task_revision并重排其全部Item，旧执行/选择失效；无关Task保留。选择只改变内容版本；显式refresh增加generation，无内容变化不制造修订。同值Patch不重复修订。
- 原授权guard、本地Task/Thread及Plan锁保护短事务，写入后复核当前执行权。完整修订、当前指针、执行安排与action回执共同提交；同Run/operation同参数返回原回执，不同参数拒绝。并发CAS仅一个成功，执行项保存失败或写入后失权均整体回滚。
- 执行输入从正式Task及其显式关联路线展开，不默认起点、日期或人数；必需字段不就绪保留blocked。正式列车departure_date/关键词数组适配旧供应方DTO，保留原接受输入证明；等价表示比较不忽略不同日期、人数、未知字段，也不把null等同缺省。
- 接受结果核验持久ExecutionRequest、当前Task版本/generation、原输入摘要与内容、要求/排序、真实证据、模式和当前授权。新执行使用`exec:<execution_step_id>`调用键；定义变更或刷新后，即使输入摘要相同也不能拿旧事实冒充重查。首次Task/generation允许按相同输入复用已核验事实，跨服务复用不生成假的本地查询。
- 选择指向当前Task版本的真实已接受候选；未知价格保持null，缺失信息保留partial，不做hard/soft资格过滤或自动预订。逐项完整ExecutionResult持久化后不可改写，转stale保留原结果。天气原始事实投影到执行结果供Replanner使用，温度等未知值不补造。证据过期后View标记stale/needs_query，不改Task定义版本。
- 用户要求核验可读消息和user角色；政策核验实际保存的授权检索片段，支持源端重新核验后的导入政策。记忆经`control.read_related_memory`授权后委托platform私有投影，只取最新有效版本；Travel另受精确memory_refs清单限制。用户SHARE锁与撤回的UPDATE锁序列化。control owner没有业务表SELECT，Travel没有platform namespace/表访问权限。
- 使用`NewWithEvidence`在本地提交前重新确认远端来源；网络调用不占PG事务，提交再核验本地执行权。已提交回执优先返回，后续来源撤回不会触发重复写入；新的业务修改仍拒绝失效来源。完整上下文及记忆写入装配仍属A12。
