# A04：Run接纳、固定期限与入口Job生命周期

2026-11-08。按原OpenSpec与单代理实施计划完成A04。当前交付为仓储/应用接缝，完整API、Worker、Eino桥和专业委派装配仍由后续任务承担。

## 实现

- `platformrun.Service.Admit`与仓储共用请求校验及原文SHA-256；同用户/会话/幂等键同内容返回原Run，同键不同内容拒绝。不同新请求在accepted/running/waiting阶段均返回run_conflict，不追加到原Run。正文16000字节及幂等键200字节边界沿用原服务。
- 接纳先取得Session/context guard和`run:active_per_user`配置共享锁，再锁用户额度行、conversation和业务对象。额度从PG非终态Run核对，包含waiting；部署须显式提供正数配置行，没有每API单独额度或无限回退。真实双连接池及不同预算配置仍共享同一额度，fixture值2不作为产品固定上限。
- Run、root Job、原Session、固定限额快照、原用户消息及accepted事件同事务保存。created_at和deadline采用锁后的同一PG时间，默认相差恰好300秒；排队、续租、接管不改写deadline或原预算，page lease不参与存活条件。
- `ClaimEntry`从持久ready/失权running记录认领；领取新epoch，续租保持epoch且拒绝过期旧租约。失权running累计原Job.retry_count，最多三次故障恢复，正常waiting→ready不额外算故障重试。认领返回原CheckpointVersion、RunVersion及LimitSnapshot。
- 已运行Job须具有匹配内核/配置、Eino版本、格式、上下文代次及SHA-256的持久断点。缺失或不兼容现场可靠interrupted；无效限额快照同样可靠终结；恢复次数耗尽为failed/retry_exhausted。原消息、断点及已提交事实不删除。
- 入口控制事务一开始持Run guard UPDATE锁，避免完成时从SHARE升级。所有A04事务显式READ COMMITTED；测试实际复现了连接默认Repeatable Read时两个旧快照突破额度1的缺口，修正后仅允许一个接纳。
- `FinishRun`检查当前worker/epoch、未过期租约、非终态及ExpectedRunVersion。最终消息、Run/Job终态、连续seq事件和guard关闭共同提交；消息或事件写入失败全部回滚。写入等待后再次核验授权、deadline和租约，再关闭guard，不能把迟到保存当成成功。
- `CloseInvalidRun`仅根据持久Run身份、实际期限/原Session撤回或过期/上下文失效收尾，调用方不能自报超时原因。platform和maintenance可执行，travel不可执行；有效Run不被收尾，重复收尾无变化，已有部分文本保留。全局timed_out走该系统入口，worker终态命令处理succeeded/failed/interrupted。

JobLease/RunView新增内部版本及限额信息；旧`model.Run`保持原状，MCP正式JSON Schema未变。可靠事件继续采用既有run_id/type/attempt/seq/payload结构，没有建立另一套规格或事件事实表。
