## MODIFIED Requirements

### Requirement: 历史保留与上下文排除
系统 MUST 保留历史用户消息、已有输出、工具调用和结果供获授权用户查看，并在组装模型输入时遵守来源有效性、清除边界和上下文代次。历史可见不等于可自动使用；旧系统已被替代或已排除的任务内容不得因本次移除暂停交互而重新进入上下文。

#### Scenario: 上下文隔离
- **WHEN** 读取旧流程中被新问题替代且已标记排除的任务历史
- **THEN** 记录仍可按原权限查看，其消息、结果和派生摘要保持原来源排除，不自动重新激活

#### Scenario: 保留更早的有效历史
- **WHEN** 会话中同时存在有效历史与已清除或已排除来源
- **THEN** 系统按预算使用允许的有效历史，只排除失效来源，不因此清空全部会话或重新使用旧断点

### Requirement: 迟到事件不能污染新任务
系统 MUST 将消息、事件、断点和工具结果关联到具体 Run/Job、原调用及有效执行版本；已终结或失去执行权的任务不得写入其他 Run、改变新任务状态或重新使旧断点有效。

#### Scenario: 迟到写入
- **WHEN** 已超时、失败或被接管的旧执行在后续 Run 活动期间提交文本、工具结果或断点
- **THEN** 系统拒绝旧执行对当前有效状态的写入，必要历史审计仍归原调用，不影响新任务上下文

## REMOVED Requirements

### Requirement: 新问题替代暂停任务
**Reason**: 用户已移除用户暂停及补充原任务交互，不再提供“发新问题替代暂停任务”的新运行路径。
**Migration**: 新请求遵守agent-execution的幂等和会话互斥，不自动取消活动Run；旧暂停记录按兼容方案处理，不删除历史、不恢复不兼容旧断点。

### Requirement: 明确区分继续与重新开始
**Reason**: 用户手动继续功能已移除，不再要求用户选择继续或重新开始。
**Migration**: 用户按普通提问交互；内部合法恢复由task-recovery的持久状态协调，不制造伪装为恢复的新用户问题。
