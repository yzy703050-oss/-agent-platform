## MODIFIED Requirements

### Requirement: 流式订阅与权威查询
系统 SHALL 提供按 Run 订阅的事件流及状态查询，文本增量、工具状态和终态有明确类型；订阅切换、连接关闭或页面离线不触发用户暂停、继续或取消任务。终态查询必须能获取持久化结果，页面重连只补接状态和事件，不重复启动执行。

#### Scenario: 订阅切换
- **WHEN** 用户从一个 Run 的事件订阅切换到另一个
- **THEN** 旧 Run 按原请求、权限和期限执行，用户可通过查询取得已保存结果

#### Scenario: 断流后查询
- **WHEN** 用户错过部分 Token 增量后重新打开任务
- **THEN** 系统返回已保存内容和权威状态；不承诺逐 Token 重放，不显示继续按钮或重复调用模型

### Requirement: 可复现交付与真实验证
系统 SHALL 提供启动说明、配置示例、数据库迁移、自动化验证命令，以及异步等待、重复消息和进程故障恢复的演示步骤；数据库、跨进程链路和真实模型验证未运行时必须明确标记未验证，不得用模拟结果代替真实验收。

#### Scenario: 未安装数据库
- **WHEN** 开发机未安装 PostgreSQL 或 Docker
- **THEN** 文档说明前置条件；正式服务不得静默切换为内存数据库，数据库集成检查不得被报告为通过

#### Scenario: 无模型凭据
- **WHEN** 未配置模型凭据
- **THEN** 普通聊天明确报告模型不可用；测试可注入模拟模型，但不能将模拟回答当作真实模型演示

#### Scenario: 未验证异步恢复
- **WHEN** 仅执行了静态材料校验或同进程假模型测试
- **THEN** 文档明确跨进程等待、消息接纳和故障恢复尚未验收，不将其描述为已经实现

## ADDED Requirements

### Requirement: 跨实例事件补读与输出快照
系统 MUST 为可靠事件提供Run内单调序号，跨API快速通知仅提示补读持久事件。临时文本增量与可靠事件游标区分；重连可由持久输出快照及最终消息重建展示，不因缺失增量重复启动执行，也不因乱序通知跳过已提交事件。

#### Scenario: 丢通知和实例切换
- **WHEN** 页面连接到另一API且错过Redis通知
- **THEN** 周期补读从持久游标恢复状态和输出，最终答案可获取，不要求原API继续存活

#### Scenario: 文本缺口或接管
- **WHEN** 临时增量缺失、重复，或旧执行代次仍发送增量
- **THEN** 客户端按当前有效流及快照替换覆盖内容，旧代次不能污染当前回答，最终消息不重复拼接

#### Scenario: 慢连接及登录失效
- **WHEN** 客户端持续无法及时接收，或Session已失效
- **THEN** 关闭该订阅并允许按权限重新查询，不阻塞Worker或把断线记成用户暂停/取消
