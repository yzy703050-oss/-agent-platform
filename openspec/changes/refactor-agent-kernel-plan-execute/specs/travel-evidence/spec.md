## ADDED Requirements

### Requirement: 共享查询与真实能力边界
系统 SHALL 向两个入口及专业规划执行器提供共享查询能力，返回真实结果、实际查询条件、来源、状态和时效。纯查询不依赖 TripPlan；未接通能力必须明确不可用，不以演示数据冒充真实事实。入口只能调用已注册且获授权的工具。

#### Scenario: 单项信息查询
- **WHEN** 用户仅查询天气、酒店或某段车次
- **THEN** 当前入口直接查询并返回结果及来源或明确失败，不自动创建计划或扩展安排

#### Scenario: 酒店能力范围
- **WHEN** 酒店供应方只返回地点，没有价格和库存
- **THEN** 系统保持价格和库存未知，不宣称可订、不生成订单、不将未知金额当作零

#### Scenario: 显式演示查询
- **WHEN** 运维明确启用已有 demo 查询模式
- **THEN** 证据和结果保留演示标识；live 失败不自动回退为演示成功，不混用两种模式

### Requirement: 共享证据与有界复用
系统 SHALL 保存可追溯到实际工具调用的查询证据，使两个入口和专业规划在既有用户、会话、来源和有效期范围内引用同一事实。证据由实际查询所属服务持有，跨平台/Travel复用须通过受控接口提供可验证的不可变内容及来源引用，不以直接共表读写绕过服务边界。证据身份不以计划身份为前提；正式计划通过执行项及选择引用证据，不另存一份可独立修改的候选事实。查询受并发、时间和重试上限保护。

#### Scenario: 先查询后规划
- **WHEN** 当前入口已查询酒店，用户随后要求形成行程
- **THEN** 规划流程读取真实证据并核对权限、输入、来源、模式及新鲜度；可复用时建立计划侧引用，不能只凭助手文本构造候选

#### Scenario: 计划 Task 变更
- **WHEN** 已执行 Task 的有效定义变化
- **THEN** 系统重新安排该 Task 的全部查询 Item，不用共享缓存绕过该重查规则

#### Scenario: 查询期间修改
- **WHEN** 查询结果返回时计划任务版本或执行代次已失效
- **THEN** 查询事实可保留审计，但不能作为当前任务完成或当前选择；共享工具成功不等于计划接受该结果

#### Scenario: 供应方失败
- **WHEN** 查询超时、限流或返回非法结果
- **THEN** 系统返回明确失败或部分结果，不无限重试、不虚构候选

#### Scenario: 其他入口的会话
- **WHEN** 同一用户在另一入口建立了不同会话
- **THEN** 系统不因复用查询底座或证据引用自动跨会话读取；仍按既有授权范围处理

## REMOVED Requirements

### Requirement: 真实查询与能力边界
**Reason**: 双入口共享查询与计划查询需要统一来源和能力边界，不沿用旧角色工具协议。
**Migration**: 由“共享查询与真实能力边界”替代；保留只回答所问、真实来源、酒店能力限制和演示标识，纯查询继续免计划。

### Requirement: 有界查询与失效结果保护
**Reason**: 查询证据不再依赖 TripPlan，计划执行仍需要独立的 Task 版本和迟到结果保护。
**Migration**: 由“共享证据与有界复用”替代；保留并发、时间限制、权限隔离、证据复用及失效保护。
