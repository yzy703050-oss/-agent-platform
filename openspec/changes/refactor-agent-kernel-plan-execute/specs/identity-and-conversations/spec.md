## MODIFIED Requirements

### Requirement: 用户数据隔离
系统 MUST 从服务端认证结果确定用户身份，对会话、消息、Run/Job、事件、断点和设置执行归属检查；客户端及模型传入的用户标识不能覆盖身份。内部委派和消息重投不得扩大用户或会话权限，不提供用户暂停或手动恢复入口。

#### Scenario: 跨用户操作
- **WHEN** 用户 B 查看、修改或订阅用户 A 的资源
- **THEN** 系统拒绝请求，不返回资源内容或触发执行

### Requirement: 会话历史与管理
系统 SHALL 提供个人会话列表及分页、消息历史及分页、会话重命名和删除；存在非终态 Run 时删除返回冲突，待其结束后可重试，不通过删除绕过执行互斥或提供整轮取消。删除后不得继续访问或恢复该会话。

#### Scenario: 历史分页
- **WHEN** 用户查看包含多页消息的本人会话
- **THEN** 系统按稳定顺序返回分页结果，不重复或遗漏边界消息

#### Scenario: 删除有活动任务的会话
- **WHEN** 用户请求删除存在非终态任务的会话
- **THEN** 返回冲突且保留任务仍使用的数据，不自动取消任务或要求点击已移除的结束按钮

## ADDED Requirements

### Requirement: 多实例登录与有效执行授权
系统 SHALL 沿用受保护 Cookie、服务端持久 Session 与 CSRF 防护，使请求可由不同 API 实例处理。撤销或过期凭证 MUST 拒绝受保护访问；执行的后续有效推进须复核授权，不把已结束 Run、页面连接或消息自报身份当作后台执行权。

#### Scenario: 跨 API 访问和撤销
- **WHEN** 在一个 API 实例登录，在另一实例查询，随后原 Session 被撤销
- **THEN** 撤销前按相同归属访问，撤销后拒绝受保护请求，不依赖丢失的缓存通知维持撤销正确性

#### Scenario: 执行中授权失效
- **WHEN** Run 的原 Session 过期或被撤销
- **THEN** 系统阻止新的有效推进，可靠记录授权失效原因和已有结果，不把它表述为用户整轮取消或撤销已发生效果

#### Scenario: 浏览器伪造写请求
- **WHEN** 写接口收到无效 CSRF 或无法验证的来源
- **THEN** 系统拒绝写入，不因其他实例拥有登录缓存而放行
