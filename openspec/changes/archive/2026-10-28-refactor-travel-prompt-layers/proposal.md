## Why

用户要求修正差旅提示词分层。当前 Go 保留了 Python 角色提示，却向各角色统一追加包含默认值、字段说明、修复策略和流程覆盖的补充；规划总结依赖后文否定旧 Verifier，重试另行替换提示，导致职责交叉、重复与输入不一致风险。

## What Changes

- 将当前有效规则整理为角色、公共行为、规划领域规则、工具说明和动态数据；运行时只加载当前职责需要的内容。
- 为 Main、规划总结、旧 Verifier 和独立查询总结提供不含相反规则的运行时角色提示；正常调用、角色切换、重试及无 flow 的 kernel 使用统一组装入口。
- 保留 Python 原项目、冻结提示、schema、SHA 和历史验收报告，建立原规则到有效层的映射，不把历史原文当作必须全文注入的运行时指令。
- 工具参数纠错说明归工具描述，错误观察保留原样；实际提示、工具描述和组装版本进入恢复指纹与审计。
- 保持现有默认条件、政策依赖、Main 一次及政策例外、总结修复权限、预算、持久化事实绑定等行为。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `travel-source-fidelity`：明确冻结迁移证据与独立版本化运行时提示的关系，增加按职责分层、一致组装和来源核对要求。

## Impact

涉及 `backend/internal/agent/agents/travel` 的提示资源、组装、重试和指纹，以及 `backend/internal/agenttools/travel` 的运行时工具描述与相关测试。无新依赖、数据库迁移、API、前端或工具权限变更；不修改 Python 项目。提示改变会使旧指纹断点按现有规则不可恢复，历史仍可查看；不自动部署或重启服务。
