## Purpose

为普通聊天建立统一、可观察且具有用户权限约束的执行过程，支持真实模型与只读工具调用，明确请求幂等、单会话执行互斥和任务状态的对外行为。

## ADDED Requirements

### Requirement: 普通聊天与授权工具
系统 SHALL 提供真实模型驱动的多轮聊天，并支持读取当前用户设置的只读工具；工具执行身份必须来自认证范围，工具结果不得跨用户泄露。

#### Scenario: 工具调用
- **WHEN** 普通聊天模型请求读取当前用户的设置
- **THEN** 系统通过业务授权后的设置能力返回结果，并产生可观察的工具开始与结束状态

#### Scenario: 不支持的工具
- **WHEN** 模型请求未注册或未授权的工具
- **THEN** 系统拒绝调用且不访问外部系统或数据，不将拒绝解释为工具成功

### Requirement: 请求幂等
系统 SHALL 对同一用户、会话和幂等键的消息提交保证只创建一个 Run 和一条对应用户消息；同键不同有效载荷必须返回冲突。

#### Scenario: 并发重复提交
- **WHEN** 两个并发请求以同一幂等键和相同有效载荷提交
- **THEN** 返回同一 Run，数据库仅存在一份对应用户消息，执行器最多启动一次

#### Scenario: 幂等键误用
- **WHEN** 已用幂等键被用于不同消息或不同执行选项
- **THEN** 系统返回 idempotency_conflict，不覆盖已有 Run

### Requirement: 执行互斥与终态
系统 MUST 防止同一会话的任务同时执行，终态不可被迟到的结果覆盖；完成消息与成功状态必须共同持久化，存储失败不得向客户端报告完成。

#### Scenario: 同会话并发
- **WHEN** 会话已有运行或正在暂停、恢复的任务，又收到不同的新请求
- **THEN** 系统返回 run_conflict，不启动第二个执行器

#### Scenario: 完成与结束竞争
- **WHEN** 完成回调与任务结束请求竞争
- **THEN** 仅接受符合当前状态和执行版本的一次状态迁移，迟到结果不改变已提交终态

### Requirement: 显式结束与执行限制
系统 SHALL 支持用户结束任务，并为执行设置总时限、模型迭代上限和工具时限；结束、超时和失败必须可区分。结束后原断点不得继续使用。

#### Scenario: 用户结束任务
- **WHEN** 用户结束一个运行或暂停的任务
- **THEN** 系统停止或确认停止执行，使断点失效，并记录 cancelled 及对应原因

#### Scenario: 执行达到限制
- **WHEN** 模型反复调用工具达到迭代上限，或执行超过时限
- **THEN** 系统以明确错误结束，不无限调用模型或工具
