## Purpose

让差旅业务通过用户已有 RAG 系统的 MCP 服务获得可引用的政策依据，保留证据来源与适用范围，明确区分检索失败、未命中和已核验规则，避免无依据地宣称差旅合规。

## ADDED Requirements

### Requirement: 复用现有政策检索服务
系统 SHALL 通过现有 RAG MCP 服务检索政策，不要求将 RAG 内核或索引迁入本平台；接入必须核验实际连接、工具入参和证据返回契约。

#### Scenario: 有效证据
- **WHEN** 现有 MCP 服务返回符合已核验契约的政策片段
- **THEN** 系统保留文档或片段来源及适用信息，供差旅规则判断和输出引用

#### Scenario: 协议不符合
- **WHEN** 服务返回的结构无法映射为有效政策证据
- **THEN** 系统报告检索或证据错误，不将其作为已验证的规则

#### Scenario: 演示政策知识
- **WHEN** 运维选择独立 agent_platform_demo 集合中的自编虚构差旅政策
- **THEN** 系统通过真实 MCP 检索并保留片段和来源，工具、界面和最终回复标明演示政策，不能据此认定正式行程或报销合规

### Requirement: 政策适用与未知状态
系统 MUST 区分规则适用、不适用和无法核验；未检索到、检索失败或依据不足时不能宣称已满足公司差旅政策。

#### Scenario: 检索不可用
- **WHEN** MCP 服务超时、不可连接或没有相关政策
- **THEN** 系统显示政策未核验及原因，对受影响结论保留缺口，不生成合规承诺

#### Scenario: 条件不适用
- **WHEN** 政策片段只适用于另一人员等级、区域或日期条件
- **THEN** 系统不能直接将该片段的限制作为当前行程已确认政策

### Requirement: 检索边界与凭据保护
系统 MUST 将检索内容视为证据数据，不能据此覆盖执行权限或发起未授权工具；连接凭据不能出现在模型输入、用户事件或断点中。

#### Scenario: 片段包含指令
- **WHEN** 检索片段包含要求改变权限或调用其他工具的文字
- **THEN** 系统不按该文字授予权限或执行额外操作
