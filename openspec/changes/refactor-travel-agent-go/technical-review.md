# 实施前技术复核

日期：2026-10-23。执行方式：用户明确选择单代理。复核依据为本 change 的 proposal、全部六份 delta specs、design、tasks、源码迁移映射，以及现有 Go/Eino/Python 实现。本文记录工程发现，不重新定义需求。

## 复核结果

| 发现 | 处理 | 对应任务 |
| --- | --- | --- |
| 入口虽有 travel，但 Handler、Application、Agent 列表与前端均有硬编码禁用；仅注册 Agent 不会开放入口 | 统一改为按会话 Agent 类型检查，保留未就绪不可用，增加一个集成场景覆盖两类 Agent | 8.1–8.2 |
| Manager 已经按会话注册表恢复；恢复探测会调用 NewExecution | Travel 构造/兼容性验证必须无模型、查询、业务写入副作用 | 2.1、6.3 |
| General 目前独占 TurnLoop 适配；直接复制会产生两份暂停修复代码 | 两个使用方确实存在时提取最小 einoruntime 包，保留现有 General 测试 | 2.1、6.3 |
| SDK workflow.go 的顺序/循环 Agent 通过全上下文转交实现且有不推荐说明 | 首选 ChatModelAgent Handlers 实现阶段约束；不把“多个阶段”误当多个平台 Agent | 2.1、6.2 |
| SDK AgentMiddleware 已标弃用，新接口可包装模型和工具并重写可见工具列表 | 使用 Handlers，工具执行处另做阶段授权，不能只隐藏工具 schema | 2.1、6.1 |
| 外部模型流可能取消在半段 JSON，不能将其视为完整业务意图 | 决策完整校验持久化后才执行工具，最终输出流与业务提交边界分开处理 | 2.2、6.2–6.4 |
| 现有消息 source_key 去重不是业务写入幂等 | 增加决策记录、稳定逻辑操作及事务回执，验证提交后断点前故障 | 2.2、4.3 |
| 业务事务与平台暂停/替代会锁相同资源 | 明确会话→Run→业务资源顺序、running/attempt 围栏；网络调用不在事务内 | 4.2–4.3、6.4 |
| 长期偏好若只覆盖当前行，替代 Run 后无法恢复更早有效值 | 使用来源可追溯的修订；摘要过滤先于压缩，混合来源失效 | 7.1–7.3 |
| RAG 服务 transport/schema 未提供，旧 stdio 协议并非已确认新服务契约 | 先实现内部 PolicyRetriever 接口；真实接入在用户提供服务后核验，不伪造成功 | 5.4–5.5 |
| Python 历史测试很多，不应逐项迁移 | 采用 design D11 四类关键测试；探针保留为正式恢复回归，平台已有测试直接复用 | 全部 |

## 尚待实施证明

- Handlers、SessionValues、完整工具决策与 TurnLoop 在指定 SDK 版本下的持久化、停止及跨实例恢复，需要实际探针，源码阅读不等于通过。
- 新增迁移的租户复合外键、修订竞争、回执原子性和旧 attempt 拒绝，需要真实 PostgreSQL 测试。
- 供应方与 RAG 真实连接尚未验证；不读取原 Python .env 获取隐式配置。

上述事项已经进入实施任务与测试，不构成已完成实现的声明。未发现需要改变用户已确认产品范围的理由。工作位置遵循用户“在这个项目里面”的明确要求，保留当前非 main/master 工作分支，不新建工作树或单独迁移仓库。
