## MODIFIED Requirements

### Requirement: 有限编排与确定性业务保护
系统 MUST 对规划、查询、校验、局部修正及重规划设置可验证的执行边界和限制；模型不能跳过业务校验或以自然语言声明代替实际提交。系统 SHALL 保留原版 Main 全局规划、Verifier 审查及局部修正、必要时交回 Main 重规划和独立查询总结的职责及工具权限，预算按原版业务批次语义累计，恢复不清零。

#### Scenario: 修正与重规划
- **WHEN** 校验发现局部问题或需要全局调整
- **THEN** 系统在允许范围内修正或重规划，达到限制则明确停止，不无限循环

#### Scenario: Verifier 权限
- **WHEN** 已有计划进入审查
- **THEN** 允许选择和原子修改当前授权行程，超出局部权限通过独立重规划交接回到 Main，保留有效成果，不直接新建替代计划或读写偏好

#### Scenario: 独立查询总结
- **WHEN** 用户仅查询信息且没有规划延续或已有行程待审查
- **THEN** 系统总结真实查询结果，不创建行程；政策观察后的规划继续交给 Main，已有行程交给 Verifier

## ADDED Requirements

### Requirement: 批次预检与可恢复执行
系统 MUST 在产生副作用前预检完整工具批次，保留原版请求类型一致、政策前置依赖、重规划独立提交、同一行程每批一次写入和有界独立动作并发规则；合法独立动作可以同批执行，每项回执与工具调用完整配对。

#### Scenario: 整批参数无效
- **WHEN** 同批工具中任一调用的预检参数或权限不合法
- **THEN** 系统在副作用发生前拒绝该批次，并提供原因及被连带中止调用的对应结果

#### Scenario: 合法独立写入
- **WHEN** 一个批次包含不同授权行程的写入或明确偏好更新与规划，且没有真实前置依赖
- **THEN** 系统按原版规则允许该批次，不以“每轮最多一个业务修改”的额外限制拒绝；同一行程仍不得并发覆盖

#### Scenario: 批次中断恢复
- **WHEN** 批次部分动作已提交，进程在后续动作或自动查询前暂停
- **THEN** 系统依据已接受决策、逐项回执和待查作业恢复，已提交动作不重复写入，未完成动作不冒充已完成
