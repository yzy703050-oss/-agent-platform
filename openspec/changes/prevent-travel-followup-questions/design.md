## Goals / Non-Goals

**Goals:** 恢复无追问交互、有效长期记忆直注和正常规划通常两次的执行路径；政策前置单列，真实重排可追加调用；保留未知起点不虚构、默认往返、软建议和确定性业务校验。

**Non-Goals:** 本轮不引入新交通供应方、全新需求问卷、额外意图分类模型或新的工具参数契约。

## Decisions

### 原版基线与有效补充分别审计

冻结的 main/review/summary/reply/rail 提示不改，增加专门的 `prompts/no_followup.txt` 补充，明确“缺省可建议、未知可陈述、不得索取补充或确认”。通过 flow.go 在全部决策角色实际输入中统一加入；补充计入 Agent 指纹，独立验证，不声称有效提示完全未改变。

补充须同时说明：新规划不要为填缺省条件查旧历史；不要把需要默认建议的情况改判成独立查询；未知起点保留缺口并继续目的地建议，不编造交通或承诺航班查询。以上均来自现有原版规则及本次用户要求。

### 验收直接判断行为

先保留当前真实失败样本，再写真实 Eino 输入与阶段切换的回归测试，核对每阶段均发送补充规则。实际模型场景至少包括截图原句、新规划缺少可默认条件、完整条件规划及普通独立查询。每类重复三次，逐条人工核对回复和动作，不只统计问号或匹配固定句式。未出现问号但仍要求补充、确认或等待，也算失败。

真实样本证明单靠提示仍偶发索取信息，因此在原生生成协议入口增加明确索取信息的有界校验：正文或绑定解释中出现明确请求时整次响应不接受、工具不执行，沿用原两次额外再生成预算，给出明确的交互纠错指令。拒绝的完整响应与原因通过 travel.model_rejected 事件保留；无法纠正则返回明确失败，不把问卷交付给用户。不删改模型句子，也不把有限语言规则宣称为通用语义理解保证。该校验只用于面向用户的 Main/Verifier/Summary 生成，不套用到政策或偏好 JSON 辅助模型。

### 长期记忆由程序注入，低频维护保持原设计

`Agent.NewExecution` 已把 `ReadPreferences` 接到按 scope/run 隔离的 `ReadEffective`；`beforeModel` 已装配 legacy_preferences、memories 和 preference_summary。沿用此直接注入入口，明确空值含义，并提取为有测试的装配逻辑，保证 Main 与 Verify 同样可见。这里的数据库读取是上下文装配，不是模型发起的用户资料读取。

直接核对 Python 后确认：`bootstrap.py:108` 原版也调用 `update_inferred_preferences`；`agents/preference.py:56` 规定每三条新增有效样本才自动归纳。本次保留 `PreferenceAgent.Maintain` 的原阈值和一次性覆盖语义，不把“不要模型主动读长期记忆”误解成删除原版归纳功能。为已有记忆重复读历史、归纳相同样本仍是退化，须通过测试和计量发现。保留 `write_memory.update` 及明确授权的 `reanalyze`。

补充提示明确已有注入即全部当前有效记忆、为空就是没有，不主动 read trip_summaries/session_summaries 来找个人偏好。对明显新规划使用本地规则收窄工具集：未出现明确历史引用或查询/修改旧行程操作时，不暴露且预检不接受 read；不增加意图分类模型。用户明确历史操作仍保留原工具。规则区分历史博物馆等地点用词与历史记录，不把有限词法匹配宣称为通用意图理解。`read` 仍服务用户明确查询或修改历史行程；不能为禁止主动读记忆而删除合法历史功能，也不能把长期记忆等同于任意历史记录。

### 两次模型调用的正常收尾

沿用既有 Main → 自动待查作业 → Verifier 路径，不重写成新的执行引擎。Main 首轮 `write_trip.propose` 包含 tripplan 与查询地图，`recordTrip`/`runJobs` 用已提交回执生成稳定作业并执行查询；自动项已有的查询不额外独立提交。

Verifier 第二轮同时审查、选候选、提交 `reply`。`ReadyReply` 已可用 `RenderedAnswer` 从成功 select/amend 回执收尾，`afterBatch` 将最终文本交回内核，不另调用 Summary。保留工具提交与事务核验，这些步骤不是新的模型调用。正常请求不得通过把请求错误标记为 lookup 而绕过 tripplan，也不得靠 `allow_repair=false` 放弃实际未满足的硬目标凑两次。模型遗漏 reply 不等于语义审查已完成。只有 select/amend 明确 allow_repair=false、实际保存回执精确匹配且业务校验完整时，才允许在工具适配层确定性绑定完整回复，并把 rendered_answer 连同原生工具结果持久化以支持安全回放。未明确结束或仍有真实阻断时按原版规则继续，避免跳过后续活动修复。

程序生成的校验缺口也改用陈述句，并只列出实际缺失字段，不能在模型遵守规则后又由渲染器输出“请补充”。Verifier 对已授权计划的整体 route_tasks 在叶字段标准化前返回可执行的 REPLAN_REQUIRED/request_replan 指引；硬活动归属修复需 Main 时不以泛化活动ID错误导致反复 amend。观察到 REPLAN_REQUIRED 后，下一次 Verifier 工具集和 preflight 收窄为单独 request_replan；Main 接手或新成功批次后解除，不自动构造模型调用、不扩大写权限，也不增加既有预算。Main 的整体路线 ID/活动归属/连续性错误保留原错误码并返回具体契约修正说明，禁止将同一跨城段拆成交通与住宿两个重复任务。

收尾缺绑定 reply、重复 select、自动项与独立 query 重叠都需明确回归。重复动作的复用落在 flow/工具业务边界，使用规范查询键及真实候选引用/修订比较，不能依据自然语言解释或仅依据 call_id 判进展。已有 journal 幂等保护恢复重放；新模型调用产生的相同动作必须另行审计，不与恢复复用混为一谈。

### 政策前置、重排与计量边界

用户已明确：政策查询不算在常规两次规划目标内；先发出 RAG 政策工具调用，观察结果后 Main 再生成 tripplan。沿用 Python `creation_registry` 和 `execute_batch` 的政策前置保护，不预设政策结果、不把 query_policy 和依赖它的 write_trip 放同批。普通旅游不查政策。

每个实际 Generate/Stream 请求均计总数，包括发起政策工具的决策及工具内部提取、低频归纳、上下文摘要和协议重新生成；同时区分政策前置、维护和业务规划。正常确定性夹具路径预期 Main/Verifier 各一次，真实模型报告两次比例、额外调用具体原因，不宣称全场景严格两次。

沿用 Python `runtime/state.py:27` 的角色切换及 `tools/registry.py:190` 的 request_replan：局部问题先 amend，整体策略不合理才单独交回 Main，保留计划身份、有效候选、硬条件及既有预算。新调用须有真实改动或新证据；仅改解释、回执或重复 selection_refs 不算进展，原版无进展保护继续适用。

### 手工核对发现的住宿覆盖回归

真实中转样本曾通过自动断言但退房早于下一段出发，漏一晚。Python 与 Go 的原程序校验都只有“出发早于退房”检查，逐晚覆盖依赖模型审查。依据既有完整需求与逐晚住宿要求，本次补齐对称的 source timeline 检查：已标 requires_hotel、前段目的地等于后段起点且计划后段出发日（有选择时以实际日期为准）晚于退房日时，返回阻断 hotel_stay_gap，不能绑定为完整回复。不改变用户硬晚数，允许 Main 按用户已授权的软出发日期重排。验收额外独立检查漏夜、固定返程与硬一晚；不修改样本日期掩盖冲突。重排Main已持有完整当前计划且规划已开始时不再暴露或接受read，历史定位仍可在开始规划前执行；Main不会为了再读同一快照耗费轮次。Go Inspect不得把旧酒店查询图当作已取消住宿的新中转任务的待查项，旧退房条件也不约束requires_hotel=false的任务；检查保留历史数据不写修订，显式新提交的越界酒店查询仍拒绝。

### 同请求内的硬晚数由程序保存

首次成功变更中已结构化为user/context且非soft的住宿晚数，按计划和目的地累计保存到FlowState.HardStayNights。后续Main/Verifier的可信TripDecisionContext携带该快照，不能通过改task_id或把一晚改标为硬两晚来放宽同请求的要求；Preview在提交前返回HARD_STAY_REQUIREMENT，Verifier须交回Main。软建议不锁定；新用户请求有独立FlowState，允许其明确修改旧行程。它不从自然语言推断新条件，也不声称全面验证任意用户原文。

### 生产事件记录链路

实际网页验收发现Manager及PostgreSQL AppendRunEvent只允许工具/phase事件，丢弃了travel.model_call和travel.model_rejected；因此不能把数据库无测量行误报为零模型调用。补齐这两种旅行事件的转发和持久化，保留run所有者、attempt及运行状态检查，并仅允许travel会话写入。model_call沿用16KB上限，完整拒绝响应使用与决策同量级的256KB上限；前端现有事件处理忽略这两类审计事件，不把拒绝问句当聊天内容显示。新PG测试经真正Manager→Repository验证记录不丢失，并覆盖格式、大小、尝试和General隔离。

### 运行产物核对

记录监听 PID、可执行文件、编译提交、源码脏状态和实际模型输入。先核对无活动任务，再替换本地后端；健康检查同时经过 8080 后端及 5173 网页代理。现有旧产物保留以便回退；本次已经完成的重启是诊断操作，不勾选后续修复任务。

## Risks / Trade-offs

- 提示测试通过但实际行为失败 → 实际模型回复为强制验收，所有失败样本保留；不以哈希测试替代。
- 未知起点被补成建议起点 → 测试明确检查不猜测北京、不创建有虚假确认来源的交通。
- 纠错扩大到普通聊天或阻断合法工具 → 仅在差旅输入增加规则；保留普通查询和完整条件规划对照。
- 旧断点指纹不匹配 → 保持已有拒绝不兼容恢复机制，不承诺旧任务无缝续跑。
