## Why

用户明确要求沿用 Python 版“不主动追问或要求确认”的差旅交互，长期记忆直接注入提示，正常无冲突规划通常只需两次模型调用；政策前置单列，真实冲突可继续重排。2026-10-25 的原句测试却先读取历史、转入查询总结并要求补齐信息。运行版本落后与当前编排问题均已取得证据，单独重启或增加禁止追问文字不能视为完整修复。

## What Changes

- 消除 travel-planning 中“必要追问”的旧规格授权，信息不足时继续可用建议并用陈述句说明真实缺口。
- 保留冻结 Python 提示字节；通过独立、可审计的补充提示明确执行缺省与禁止追问规则，覆盖 Main、Verifier、Summary。
- 长期记忆由程序按用户和有效来源读取后直接注入 Main 与 Verify 的输入；普通规划不主动查用户资料、历史或记忆，不为取得已有偏好额外分析。沿用 Python 原版有阈值的低频偏好归纳并单列维护成本。
- 正常路径固定为用户 query → Main 一次生成 tripplan 与查询地图 → 程序执行工具 → Verify 一次审查、选择、提交绑定回复 → 工具回执直接呈现。Verify 同时负责总结，不追加第三次 Summary 调用。
- 正常路径以两次模型调用、相同查询零重复、无进展选择零重复为效率目标，不设置两次硬上限。政策前置与维护单列；所有实际模型调用仍保留总账，真实修复有原因、保留成果，不用重复动作凑进展。
- 将原句及缺少人数、返程、住宿等条件的场景加入实际模型验收。提示哈希相同、运行成功、已产生文本均不能证明行为通过。
- 交付核对实际监听进程的编译版本、实际模型输入与浏览器代理，避免验证代码与网页运行版本脱节。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `travel-planning`：信息不足时禁止追问、索取确认或等待补齐才继续；保留原有默认建议及未知事实边界。
- `travel-memory`：有效长期记忆直接注入，普通规划不额外主动检索已有偏好，保留有阈值的低频归纳。
- `travel-execution`：正常无冲突规划通常两次模型调用；政策先查后规划，真实修复允许额外轮次，避免无进展重复动作。
- `travel-source-fidelity`：明确记忆直注、原版低频分析与分阶段调用审计口径。

## Impact

涉及差旅补充提示、上下文注入、偏好分析触发点、收尾路径、指纹、场景测试及调用审计；不改冻结 Python 源码。实施须隔离其他任务的联网搜索改动。本提案阶段不修改产品代码。
