## MODIFIED Requirements

### Requirement: 完整需求驱动的审查与校正
系统 MUST 将原请求、最新明确修改、全部相关行程、活动日历、真实候选与选择、政策、偏好及修改历史提供给相应决策阶段；审查不能只检查首段或以字段齐全替代用户目标满足。有效长期记忆 SHALL 直接注入模型输入，普通规划不通过模型主动读取资料或额外分析来获取已有记忆。

#### Scenario: 多城与必要住宿
- **WHEN** 用户要求多个目的地、活动、住宿和返程
- **THEN** 规划与审查覆盖全部需求、完整日期和逐晚住宿，遗漏须实际修复或明确说明未满足，不能只完成第一段后声称完成

#### Scenario: 默认返程与明确单程
- **WHEN** 用户没有明确单程，或明确要求单程
- **THEN** 系统分别沿用原版默认往返建议或显式单程语义，建议条件保留其可调整来源和强度

#### Scenario: 原版政策依赖
- **WHEN** 明确出差或用户明确要求政策，且政策影响规划
- **THEN** 系统先观察真实政策结果再确定受影响条件；保留原版证据提取、引用与规则核验，资料不足不等于无限制；普通旅游和无关查询不额外检索政策

#### Scenario: 偏好与上下文
- **WHEN** 构建规划或审查输入
- **THEN** 有效偏好直接注入并支持明确更新；保留原版有新增有效样本门槛的低频归纳及显式重分析，普通规划不重复检索已有偏好；预算压缩继续适用，维护与压缩等实际模型调用单列并计入总数，来源仍遵守任务隔离，不读入被替代任务或 Python 旧用户数据
