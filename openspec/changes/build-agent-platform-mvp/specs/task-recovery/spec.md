## Purpose

使用户可以关闭页面停止任务，并在再次打开后查看保存状态、手动从有效断点继续，同时区分正常暂停与服务故障，避免把仅有历史消息的任务错误标记为可恢复。

## ADDED Requirements

### Requirement: 页面级执行归属
系统 SHALL 将执行绑定到发起任务的页面；页面内切换会话或 Agent 不暂停旧任务，关闭发起页面则触发其活动任务的暂停。其他打开的页面不能仅因存在而阻止该暂停。

#### Scenario: 页面内切换
- **WHEN** 用户在页面内切换历史会话或 Agent 入口，但页面仍保持在线
- **THEN** 原任务继续执行，事件订阅变更不被当作页面关闭

#### Scenario: 关闭发起页面
- **WHEN** 发起任务的页面离线被服务端确认，即使另一个标签页仍在线
- **THEN** 系统对该页面的活动任务请求暂停；网络检测存在有限超时，不能保证关闭瞬间完成暂停

### Requirement: 安全暂停与有效断点
系统 MUST 区分 pausing、paused 与无法恢复的中断；暂停等待有上限，只有执行已停止且有效断点已持久化才允许报告 paused。

#### Scenario: 成功暂停
- **WHEN** 任务在等待上限内到达支持的停止边界并保存有效断点
- **THEN** 系统记录 paused，保留断点引用与已有显示结果，不再继续模型或工具步骤

#### Scenario: 保存失败
- **WHEN** 暂停时断点写入失败或执行无法确认停止
- **THEN** 系统不得报告可恢复的 paused，明确记录暂停失败或中断原因，不盲目重新执行工具

### Requirement: 重开只展示与手动恢复
系统 SHALL 在重开会话时展示历史、已有输出及任务状态；只有用户显式继续才调用内核恢复。恢复前必须检查权限、断点有效性、执行版本和任务是否仍允许继续。

#### Scenario: 重开会话
- **WHEN** 用户打开有暂停任务的历史会话
- **THEN** 展示暂停状态和继续入口，不调用模型或工具

#### Scenario: 重复继续
- **WHEN** 用户并发点击两次继续，或两个标签页同时恢复同一任务
- **THEN** 最多一个恢复执行启动，其他请求返回已有状态或明确冲突；成功恢复后执行归属转移到恢复发起页面

### Requirement: 重启后判定恢复能力
系统 SHALL 在单实例服务重启后识别非终态任务，仅对存在有效且兼容断点的任务提供手动恢复，不自动启动任务。

#### Scenario: 有效断点
- **WHEN** 服务重启后发现旧执行和有效兼容断点
- **THEN** 系统确认旧实例不再执行后将任务列为可恢复暂停，并等待用户继续

#### Scenario: 无有效断点
- **WHEN** 服务重启后发现旧执行没有有效断点，或断点版本不兼容
- **THEN** 系统标记为 interrupted 且不可恢复，保留历史并解释原因

### Requirement: 断点不保证外部副作用回滚
系统 MUST 保留已知工具执行结果；当外部写入结果未知时不能通过恢复自动重试该写入，暂停或结束任务不能被解释为撤销已发生的外部操作。

#### Scenario: 外部结果未知
- **WHEN** 外部操作可能已经成功但本地未收到确认
- **THEN** 系统显示待核实或明确失败状态，不宣称无副作用地从原位置恢复
