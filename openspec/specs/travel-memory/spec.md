# travel-memory Specification

## Purpose
使差旅偏好和上下文压缩进入平台统一的身份与存储边界，保存可追溯的偏好修订和摘要来源，并在用户结束旧任务重新发问时可靠排除旧信息，避免长期记忆绕过任务上下文隔离。

## Requirements

### Requirement: 从新数据开始
系统 SHALL 从 Go 平台新产生的数据建立差旅业务和记忆，不导入原 Python 项目的行程、历史、偏好、摘要和断点；本次重构不删除原项目数据或现有平台历史。

#### Scenario: 初始化 Go 差旅
- **WHEN** 新差旅功能首次启用
- **THEN** 系统不读取原 Python 用户数据库建立偏好或恢复旧执行，已有 Go 平台用户和会话保持可用

### Requirement: 偏好修订与来源
系统 SHALL 支持明确偏好的保存和撤回，并记录来源任务及修订；有效偏好按用户隔离，自动推断不得覆盖明确偏好或复活已撤回信息。

#### Scenario: 明确保存及撤回
- **WHEN** 用户保存某项差旅偏好，之后明确撤回
- **THEN** 系统持久化相应修订，后续不继续应用已撤回值，其他用户不受影响

#### Scenario: 推断冲突
- **WHEN** 历史分析得出的偏好与用户明确要求冲突
- **THEN** 系统不以推断覆盖用户明确要求

### Requirement: 偏好和摘要遵循任务隔离
系统 MUST 从后续自动上下文排除被新问题替代任务产生的偏好及摘要；混合摘要含有被排除来源时不得继续直接使用，同时保留更早仍有效的信息。

#### Scenario: 排除旧任务偏好
- **WHEN** 暂停任务保存了独特偏好，之后被新问题替代
- **THEN** 新任务及后续自动上下文不包含该偏好，不因全局记忆读取而重新带入

#### Scenario: 回退有效修订
- **WHEN** 被排除的偏好修订覆盖过更早仍有效的偏好
- **THEN** 系统不使用被排除值，仍可选取更早有效修订

#### Scenario: 混合摘要失效
- **WHEN** 摘要包含多个来源任务，其中一个被排除
- **THEN** 系统停止使用该摘要，从允许来源重建或暂时不提供摘要，不泄露被排除内容

### Requirement: 上下文预算与压缩完整性
系统 MUST 在上下文预算内保留工具调用和结果的完整配对，压缩过程不能伪造证据或改变已确认事实；预算不足时明确处理，不截断出无法解释的半个工具调用。

#### Scenario: 超预算上下文
- **WHEN** 差旅历史和证据超过允许上下文预算
- **THEN** 系统按有效来源选择或压缩上下文，工具配对保持完整，无法满足预算时返回明确限制

### Requirement: 有效长期记忆直接注入
系统 MUST 在差旅 Main 及 Verify 的实际模型输入中直接提供当前用户允许使用的有效长期记忆及已有偏好摘要；装配由程序完成，不要求模型先调用工具读取用户资料、长期记忆或历史。空记忆 SHALL 明确作为无已有偏好处理，不触发补读、分析或用户追问。注入仍遵循有效修订、撤回、来源任务隔离及用户本轮明确要求优先的规则。

#### Scenario: 带偏好的正常规划
- **WHEN** 用户有有效高铁席别及酒店偏好并发起新规划
- **THEN** 首次 Main 输入及后续 Verify 输入直接包含这些偏好，模型无需先读取资料或历史；本轮明确要求覆盖冲突偏好

#### Scenario: 无偏好
- **WHEN** 用户没有长期记忆或可用偏好
- **THEN** 输入明确表示为空，系统继续按已有默认和软建议规划，不因空值查询历史或等待用户补齐

#### Scenario: 撤回与任务隔离
- **WHEN** 某条记忆已撤回、来源任务被排除或属于其他用户
- **THEN** Main 和 Verify 的实际输入均不包含该值，不能通过补读历史重新带入

### Requirement: 偏好归纳遵循原版低频触发
系统 SHALL 保留 Python 原版每三条新增、已确认、有效且未覆盖行程触发的低频偏好归纳，以及用户明确请求的重新分析。普通规划 MUST 直接使用已有有效记忆，不为读取已有偏好触发分析；不足阈值或没有新增有效样本时不调用分析模型。归纳维护成本 MUST 单列并计入全部实际模型调用，不与正常 Main/Verify 轮次混淆。

#### Scenario: 已覆盖历史
- **WHEN** 用户已有大量历史但新增未覆盖的已确认有效行程不足三条
- **THEN** 系统注入已有有效记忆，不因历史总量或开始新规划重复调用偏好分析模型

#### Scenario: 达到维护阈值
- **WHEN** 三条新增且未覆盖的已确认有效行程满足原版条件
- **THEN** 系统按原版执行一次低频归纳并更新覆盖记录，后续相同样本不重复归纳，维护调用单列且不冒充普通规划两次的一部分

#### Scenario: 显式记忆操作
- **WHEN** 用户明确要求记住、撤回偏好或重新分析历史偏好
- **THEN** 系统执行对应授权操作；普通保存和撤回不额外调用分析模型，重新分析单独记录其调用及结果
