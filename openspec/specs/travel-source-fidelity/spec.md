# travel-source-fidelity Specification

## Purpose
确保现有 Python 差旅助手迁移到 Go 平台时保留已经设计的决策、工具交互、校正和回复行为，使用户能依据原版能力使用差旅入口，并能通过固定源码基线及真实业务结果核验迁移完整性，而不是接受另一套简化的差旅助手。

## Requirements

### Requirement: 原版提示与工具契约保真
系统 MUST 保留已冻结 Python 源码的完整角色提示、共享回复规则及工具说明，保留模型可见工具名称、参数语义和阶段授权；语言迁移和内部数据映射不能悄然缩短、改写或遗漏这些约定。

#### Scenario: 完整提示校验
- **WHEN** 验证 Go 差旅角色及其工具说明
- **THEN** 静态文本与冻结原文逐字对应，动态提示使用固定输入验证组成与内容，不能以长度或个别关键词相同代表保真

#### Scenario: 原版工具动作
- **WHEN** 模型提交原版允许的规划、选择、增量修改、读取、查询、偏好更新或重规划动作
- **THEN** 系统按原版阶段权限和参数语义处理，内部映射保留字段来源、强度、缺省、显式清空及修订引用的区别

### Requirement: 完整需求驱动的审查与校正
系统 MUST 将原请求、最新明确修改、全部相关行程、活动日历、真实候选与选择、政策、偏好及修改历史提供给相应决策阶段；审查不能只检查首段或以字段齐全替代用户目标满足。

#### Scenario: 多城与必要住宿
- **WHEN** 用户要求多个目的地、活动、住宿和返程
- **THEN** 规划与审查覆盖全部需求、完整日期和逐晚住宿，遗漏须实际修复或明确说明未满足，不能只完成第一段后声称完成

#### Scenario: 默认返程与明确单程
- **WHEN** 用户没有明确单程，或明确要求单程
- **THEN** 系统分别沿用原版默认往返建议或显式单程语义，建议条件保留其可调整来源和强度

#### Scenario: 原版政策依赖
- **WHEN** 明确出差或用户明确要求政策，且政策影响规划
- **THEN** 系统先观察真实政策结果再确定受影响条件；保留原版证据提取、引用与规则核验，资料不足不等于无限制；普通旅游和无关查询不额外检索政策

#### Scenario: 偏好与上下文
- **WHEN** 构建规划或审查输入
- **THEN** 原版偏好使用、明确更新、低频有效历史分析及预算压缩继续适用，但数据来源必须先遵守平台任务隔离，不能读入被替代任务或 Python 旧用户数据

### Requirement: 有限校正与真实收尾
系统 SHALL 沿用原版错误反馈、证据刷新、无进展检测、预算计数和收尾规则；可用部分结果应真实保留，不能反复执行没有新增证据或业务进展的修改。

#### Scenario: 无进展
- **WHEN** 业务审查内容连续不变，只有回执或解释文本变化
- **THEN** 系统依原版无进展规则停止，展示真实可用结果和具体缺口，不继续无效修复或伪称完成

#### Scenario: 已知缺口的部分结果
- **WHEN** 已保存可用安排仍有政策、报价等无法核验的缺口，且满足原版部分结果收尾条件
- **THEN** 系统允许有界收尾，区分完成执行、保存行程与满足全部目标，不为消除未知状态无限重试

#### Scenario: 可修正参数错误
- **WHEN** 工具参数、约束或候选引用不合法
- **THEN** 系统返回安全且具体的原版错误语义和字段信息供模型校正，不将所有原因压成同一条“候选可能过期”提示

### Requirement: 迁移证据与测量口径
迁移交付 MUST 核对原版行为映射、实际保存结果及关键执行轨迹，并披露真实模型测量的成功与失败；不能以用例数量、模型文字或没有运行错误证明迁移完成。

#### Scenario: 代表性测量
- **WHEN** 验收独立查询、单程、多城和局部活动修改
- **THEN** 使用真实模型及明确标注的固定模拟工具，记录输入/输出 Token、端到端测量范围、各阶段模型调用与耗时、工具调用、实际业务结果及失败原因；不运行 Python 模型对照评测

#### Scenario: 仍存在失败
- **WHEN** 关键场景没有完成原请求或未实际保存修改
- **THEN** 如实报告失败，保留未完成任务，不归档为已完成，不用扩大预算或改写提示词替代遗漏行为修复
