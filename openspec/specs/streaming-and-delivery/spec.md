# streaming-and-delivery Specification

## Purpose
提供与任务执行解耦的流式事件、可信状态查询、基础诊断信息和可复现交付，使用户和开发者可以验证任务结果、隔离错误并在明确环境条件下运行这个平台。

## Requirements

### Requirement: 流式订阅与权威查询
系统 SHALL 提供按 Run 订阅的事件流及状态查询，文本增量、工具状态和终态有明确类型；事件订阅关闭不直接终止任务。终态查询必须能获取持久化结果。

#### Scenario: 订阅切换
- **WHEN** 用户从一个 Run 的事件订阅切换到另一个
- **THEN** 旧 Run 不因此暂停，用户可通过查询取得其已保存结果

#### Scenario: 断流后查询
- **WHEN** 用户错过部分 Token 增量后重新打开任务
- **THEN** 系统返回已保存的内容和权威状态；不承诺逐 Token 重放或恢复中断模型请求的 Token 位置

### Requirement: 慢订阅者与错误可见性
系统 SHALL 使用有界事件缓冲或同等资源控制，不能因客户端不读取而无限占用内存或阻塞持久化；失败必须有可定位的错误代码。

#### Scenario: 慢客户端
- **WHEN** 订阅者长期不消费事件
- **THEN** 系统关闭或降级该订阅，任务状态与终态仍可查询，不无限增长缓冲

### Requirement: 诊断与敏感信息保护
系统 SHALL 输出可关联请求、Run、执行尝试和工具耗时的结构化日志及基础运行指标；日志、事件和错误不得包含密码、模型 API Key 或明文登录令牌。

#### Scenario: 模型错误
- **WHEN** 模型服务失败且返回可能包含敏感请求信息的错误
- **THEN** 用户获得明确错误代码，日志可定位 Run，但不暴露凭据或完整敏感请求

### Requirement: 可复现交付与真实验证
系统 SHALL 提供启动说明、配置示例、数据库迁移、自动化验证命令和暂停恢复演示步骤；数据库和真实模型验证未运行时必须明确标记未验证，不得用模拟实现结果代替。

#### Scenario: 未安装数据库
- **WHEN** 开发机未安装 PostgreSQL 或 Docker
- **THEN** 文档说明前置条件；正式服务不得静默切换为内存数据库，数据库集成检查不得被报告为通过

#### Scenario: 无模型凭据
- **WHEN** 未配置模型凭据
- **THEN** 普通聊天明确报告模型不可用；测试可注入模拟模型，但不能将模拟回答当作真实模型演示
