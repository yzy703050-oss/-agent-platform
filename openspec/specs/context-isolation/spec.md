# context-isolation Specification

## Purpose
分离供用户查看的完整会话历史和实际发送给模型的任务上下文，使用户用新问题替代暂停任务时保留可见记录，又能可靠阻止旧任务内容和旧断点进入后续执行。

## Requirements

### Requirement: 新问题替代暂停任务
系统 SHALL 在暂停会话收到新问题时结束旧任务，使其断点失效，并为新问题创建新 Run；重复提交不得重复结束或重复创建任务。

#### Scenario: 发问而非继续
- **WHEN** 用户在存在暂停任务的会话中直接发送新问题
- **THEN** 系统将旧任务记录为 cancelled，原因 replaced_by_new_query，再创建新任务；旧任务不能继续

### Requirement: 历史保留与上下文排除
系统 MUST 保留被替代任务的用户消息、已有输出、工具调用与结果供查看，但从新任务及其后续任务的模型上下文中排除这些内容。

#### Scenario: 上下文隔离
- **WHEN** 旧任务包含独特文本和工具结果，用户用新问题替代任务
- **THEN** 历史查询仍包含这些内容，模型输入和后续自动组装上下文不包含这些内容

#### Scenario: 保留更早的有效历史
- **WHEN** 同一会话在被替代任务之前还有已完成的有效任务
- **THEN** 更早历史仍按正常上下文预算选取，仅被替代任务的内容被排除

### Requirement: 迟到事件不能污染新任务
系统 MUST 将消息、事件和断点关联到具体任务及执行版本；被替代任务的迟到回调不得写入新任务或重新使旧断点有效。

#### Scenario: 迟到写入
- **WHEN** 旧执行在新任务启动后提交文本、工具结果或断点
- **THEN** 系统依据旧执行版本拒绝有效状态写入，不影响新任务上下文

### Requirement: 明确区分继续与重新开始
系统 SHALL 区分继续原任务和提交新问题；继续保留原任务有效上下文，重新开始不使用旧任务断点。

#### Scenario: 点击继续
- **WHEN** 用户显式继续一个有效暂停任务而未提交新问题
- **THEN** 恢复原 Run 的上下文，不创建伪装成恢复的新问题任务
